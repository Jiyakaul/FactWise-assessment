Problem Understanding (My Approach as a Product Manager)

The quarantine facility is facing an operational crisis: 74 patients (100% full occupancy), an aggressive virus with a 15% mortality benchmark, and severe staff burnout. After analyzing the head doctor's feedback, the root issues aren't lack of effort—they are uncoordinated handoffs:

  • Unsynchronized Rounds: Doctors visit before nurses take vitals, wasting physician bandwidth on routine temperature measuring.
  • Discharge Bottlenecks: Patients who meet the 3-day fever-free rule stay an extra 1–2 days because communication to the front desk is manual. This blocks waiting patients from entering the 74 beds.
  • Zero Performance Feedback: The facility cannot see whether its treatment quality matches the 85% success benchmark.

Q3) Logical Constraints & Edge Cases for Developers

Beyond screens, developers need strict business logic so the system prevents human errors in an understaffed clinic:

1. Sequential Rounding Constraint (Nurse-First Rule)

  • At 00:00:00 every night, daily vitals flags reset.
  • If a doctor opens a patient whose nurse check is still pending, display an amber warning: "Warning: Temperature has not been recorded today by a nurse."
  • If the doctor decides to take the temperature anyway, allow manual intake right inside the modal, tag it as recordedBy: "doctor", and clear the nurse's pending item so duplicate vitals aren't taken later.

2. The 3-Day Fever-Free Cure Rule (Strict Reset Engine)

  • Fever Definition: Body temperature $T \ge 100.4^\circ\text{F}$ ($38.0^\circ\text{C}$).
  • Strict Reset: If a patient has 2 fever-free days and logs $100.5^\circ\text{F}$ on Day 3, the counter strictly resets to Day 0. No exceptions.
  • Gated Sign-off: The "Sign Discharge Order" button is hard-disabled until consecutiveFeverFreeDays ≥ 3.
  • Two-Stage Release: Doctor approval sets status to doctor_approved_discharge. The bed is NOT vacated until Admin completes the checkout, ensuring front desk is never out of sync.

3. Capacity & Metric Integrity

  • Hard 74-Bed Limit: New intake is disabled if active patients $= 74$. Trying to force-submit returns an error: "Facility at maximum capacity (74/74 beds)."
  • Closed Cases Formula: To prevent distorting mortality with patients currently undergoing treatment, compute rates on closed outcomes: $$\text{Mortality Rate} = \frac{\text{Deceased}}{\text{Discharged Cured} + \text{Deceased}} \times 100, \quad \text{Cure Rate} = \frac{\text{Discharged Cured}}{\text{Discharged Cured} + \text{Deceased}} \times 100$$
  • Benchmark Warning: If Mortality Rate > 15.0%, trigger an alert banner across leadership dashboards.

  2. The Optimal Knapsack Selection {A, B, D, F, G, H, I, J}:
    • Effort: $1.0 + 3.0 + 2.0 + 1.0 + 0.4 + 0.5 + 0.3 + 0.1 = \mathbf{8.3\text{ SP}}$
    • Total Value Delivered: $6 + 6 + 3 + 3 + 1 + 1 + 1 + 1 = \mathbf{22\text{ Units}}$
    • Safety Buffer Remaining: $10.0 - 8.3 = \mathbf{1.7\text{ Story Points}}$
My Decision as TPM: Add Features A, B, D, F, G, H, I, and J to the sprint.
Why? Feature C is a "trap" (5 points for only 6 value). By trading C for D and all low-effort items, we deliver 22 Value units instead of 21, while using only 8.3 points instead of 10.0. This leaves a 1.7-point (17%) buffer, which protects the team against unforeseen bugs or hospital emergencies.

Future Scope & Out-of-the-Box Product Ideas (v2 Roadmap)

To take this solution from a simple MVP to an enterprise-grade medical platform, here are key enhancements I would prioritize:

  1. Bedside Barcode / QR Wristband Scanning: In an understaffed ward, nurses can easily confuse patients in neighboring beds. Equipping tablets with barcode scanners to scan patient wristbands ensures 100% data integrity before logging vitals.
  2. Offline-First Progressive Web App (PWA): Quarantine facilities often have thick concrete or shielded walls that drop Wi-Fi connectivity. Using service workers and local IndexedDB caching ensures nurses can log vitals completely offline; records sync automatically when back in Wi-Fi range.
  3. HIPAA / DISHA Compliant Role Permissions: Ensure strict field-level masking. Nurses need bed numbers and vitals; admin staff need intake and billing; only licensed physicians should access full medical histories.
  4. Bluetooth BLE Smart Thermometer Integration: Pairing the web app with contactless digital thermometers via Web Bluetooth API can auto-populate temperatures with zero typing, saving ~30 seconds per bed (37 minutes saved per nurse shift across 74 beds).
